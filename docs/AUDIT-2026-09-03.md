## Findings corrected during the audit

### 1. Subgroups could be ejected from their parent

Severity before correction: High  
Status: Fixed and browser-verified

Creating a subgroup from only some meshes inside a larger group used the parent of the meshes' current group. That placed the new subgroup one level too high, sometimes at root.

The parent calculation now uses each directly selected mesh's immediate `groupId` in `app/modules/meshes.js:18976`. Browser verification confirmed that grouping two meshes from a three-mesh parent produces one outer group containing the new two-mesh child group and the remaining direct mesh.

### 2. Nested Ungroup removed too much hierarchy

Severity before correction: High  
Status: Fixed and browser-verified

Ungroup previously used the recursive split operation. It now calls the one-level dissolve operation for both a directly selected group and hierarchy groups. Browser verification confirmed that dissolving an inner two-mesh child leaves one outer group containing all three meshes.

### 3. Generated runtime and modular MCP source disagreed

Severity before correction: High  
Status: Fixed

The generated runtime exposed `objects.combineShell`, but its modular source and MCP server registration had not been included in the first isolated commit. The source operation is now present in `app/modules/mcp-bridge.js:340`, implemented at `app/modules/mcp-bridge.js:536`, and dispatched at `app/modules/mcp-bridge.js:730`. The matching MCP tool and smoke coverage were committed, and `studio-test-bundle.js` was regenerated from the modular source.

### 4. Release version references were inconsistent

Severity before correction: High  
Status: Fixed

Package metadata, the bundler output, web build, local server, and smoke expectations now use `49.61.17`. The `49.61.18` query on `studio-test-bundle.js` is only a browser cache-busting token; it does not identify a different software release.

## Open findings

### 1. Vertex Lines can become stale after later vertex movement

Severity: Medium  
Status: Open

Vertex Lines store endpoint coordinates in `manualTopologyEdges` around `app/modules/meshes.js:6818`. Face and component edits replace geometry in `app/modules/meshes.js:15099` and `app/modules/meshes.js:15148`. Existing remapping around `app/modules/meshes.js:17100` covers protected bevel edges, but it does not update `manualTopologyEdges`.

Impact: after moving a vertex used by a Vertex Line, the saved construction edge may still refer to the old coordinate. Its overlay and hole-loop splitting can then become inaccurate.

Recommended correction: remap Vertex Line endpoints alongside moved vertices, or invalidate a line when either saved endpoint no longer exists. Add a save/reload test after moving a connected vertex.

### 2. Combine into Shell collapses differing materials and colors

Severity: Medium  
Status: Open

Both shell-generation paths use shared material data only when every source agrees; otherwise they fall back to the first mesh's material/color. The relevant fallbacks are at `app/modules/meshes.js:19998-20013` and `app/modules/meshes.js:20133-20148`.

Impact: combining differently colored or textured parts can make the output appear to lose color or inherit the first selected mesh's appearance.

Recommended correction: preserve source material regions, generate an atlas similar to Merge Mesh, or show an explicit warning before collapsing materials.

## Areas checked with no regression found

- Inner-child Ungroup now preserves the outer group.
- Creating a subgroup from a parent subset now preserves the parent hierarchy.
- Group, Merge Mesh, and Combine into Shell retain multiple checked mesh rows.
- The original Line Tool remains separate and unchanged by the new Vertex Line tool.
- Axis-constrained face movement changes only the selected world axis.
- Group records, hierarchy IDs, material fields, and Vertex Lines are serialized and restored by the project format.
- No new import/export wiring regression was identified by source inspection.
